# Prompt Engineering

## 한 줄 정의
프롬프트 엔지니어링은 모델 가중치를 바꾸지 않고 입력(지시, 예시, 맥락, 형식)을 설계해서 원하는 출력을 안정적으로 얻는 기술입니다.

## 핵심 원칙
- **명확하고 구체적으로**: 목적, 대상 독자, 길이, 형식을 명시합니다. 모호함은 편차를 키웁니다.
- **역할과 맥락 주기**: 시스템 프롬프트에 역할, 제약, 배경지식을 적습니다.
- **예시 제공(Few-shot)**: 좋은 예와 나쁜 예를 함께 주면 형식 준수율이 높아집니다.
- **구조화**: XML 태그 등으로 지시, 문서, 질문을 구분합니다. 예: `<documents>...</documents>`.
- **출력 형식 지정**: JSON 스키마나 구조화 출력 기능을 쓰면 파싱이 안정적입니다.
- **생각할 공간 주기**: 복잡한 문제는 [[Chain-of-Thought|단계적 추론]]을 유도합니다.

## RAG 프롬프트 패턴
- 검색된 문서를 태그로 감싸고, "문서에 근거가 없으면 모른다고 답하라"는 규칙을 둡니다.
- 답변에 출처(문서 제목)를 표기하게 합니다.
- 이 두 가지로 [[Hallucination|환각]]을 줄일 수 있습니다.

## 프롬프트 인젝션
사용자 입력이나 검색된 문서 안에 "이전 지시를 무시하라" 같은 문장이 들어올 수 있습니다. 외부 데이터는 지시가 아닌 데이터로 취급하도록 프롬프트에 명시하고, [[Guardrails]]를 함께 적용합니다.

## 실무 팁
- 프롬프트도 코드처럼 버전 관리하고, 평가셋으로 회귀 테스트를 합니다.
- 한 번에 여러 가지를 바꾸지 말고 하나씩 바꿔 가며 효과를 측정합니다.
