# LLM Observability

## 한 줄 정의
LLM 관측성은 LLM 애플리케이션의 요청을 로그, 메트릭, 트레이스로 기록해서 품질, 지연, 비용, 오류를 추적하고 원인을 분석할 수 있게 하는 것입니다.

## 무엇을 수집하나
### 메트릭
- 요청 수, 에러율, 지연시간(p50/p95/p99)
- **TTFT**(첫 토큰까지의 시간), 초당 출력 토큰 수
- 입력/출력 토큰 수와 이를 기반으로 추정한 비용
- 에이전트 단계 수, 도구별 호출 횟수와 지연
- 검색된 문서 수, 사용자 피드백(좋아요/싫어요) 비율

### 로그
- 요청 ID와 사용자 ID(가명화), 모델 ID, 프롬프트 버전
- 도구 호출 입출력의 요약
- 에러 스택. 구조화된 JSON 로그로 남겨야 검색과 집계가 쉽습니다.
- 개인정보가 담긴 프롬프트 원문은 마스킹하거나 보관 기간을 제한합니다.

### 트레이스
하나의 질문이 "검색 → LLM 호출 → 도구 실행 → LLM 호출"로 이어지는 과정을 스팬 트리로 기록합니다. OpenTelemetry의 GenAI 시맨틱 컨벤션을 쓰면 벤더 중립적으로 수집할 수 있습니다.

## 도구
- **범용**: Prometheus + Grafana, CloudWatch, Datadog.
- **LLM 특화**: LangSmith, Langfuse, Arize Phoenix. 프롬프트와 응답을 트레이스 단위로 보여줍니다.

## 실무 팁
- 모든 로그에 요청 ID를 넣어 웹 서버와 API 서버의 로그를 연결합니다.
- 비용 메트릭에는 알람을 걸어 둡니다. 에이전트 루프 버그는 비용 폭주로 이어지기 쉽습니다.
- 사용자 피드백을 [[RAG 평가]] 데이터셋 확장에 활용합니다.
